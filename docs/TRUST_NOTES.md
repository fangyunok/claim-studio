# Trust Notes

本页说明 claim-studio 在审校与发布链路上的"可被审计、可被校验"特性，集中回答"何时可以信任一条修订文案"。这是一份**口径说明**，不是认证证书。

## 信任前提

claim-studio 的设计前提是：模型对营销文案的字面规则与引用结构做出**确定性**判断，**语义支持**仍由编辑在审核环节判定。这一前置贯穿全产品，体现在四层硬约束上：

1. **隔离**：审校只在请求中给定的 `product_id` 范围内检索事实卡；跨产品事实卡不会出现在同一候选池中。
2. **校验**：每条引文都是源 URL 内容的逐字子串，由程序在校准环节验证。
3. **绑定**：人工确认同时绑定文案摘要 SHA256 与审核包 SHA256，文本或资料任一改变，旧确认失效。
4. **可观测**：每一次审校都生成可追溯的事件链（请求体 → 工具调用 → 模型输出 → 字面规则结果），并跨进程生成 trace id。

## 审计日志

| 维度 | 落点 |
| --- | --- |
| 全部审校请求与返回 | 服务层 JSON 日志 + FastAPI 中间件注入的 `X-Trace-Id` |
| 模型调用次数与 token | `audit_bundle.json::usage` 字段 |
| 工具调用轨迹 | `audit_bundle.json::trace` 字段 |
| 字面与数字规则输出 | `audit_bundle.json::original_checks` / `revised_checks` |
| 人工确认记录 | 永久审计日志，写入 SHA256 + 审核者署名 |
| 模型 A/B 对照 | `runs/<runs_id>/` 完整审核包外加 `reports/model-size-ab.json` |

审计日志按 `runs/<run_id>/` 落盘到本地磁盘；服务层的访问痕迹由中间件沿 `X-Trace-Id` 串联。**默认落点只在本机**，无第三方上云。

## 数据隔离

- 知识库是**人工整理**的资料快照，每个 `product_id` 独立检索上下文；
- 检索层强制按请求 `product_id` 过滤，即便用户输入其他产品的关键词，返回候选仍然按本产品筛选；
- 文件层路径检查（`resolve()` 后必须在 `output_root` 下）防止 `path traversal`。

## 审批门

`scripts/approval_gate.py` 默认拒绝覆盖同版本语料，需 `--force-replace --sign-by <reviewer> --note <reason>` 三段同时给出。签名写入不可改写的审计日志。该门对应 v0.4.0 起的数据更新流程。

## 哨兵

| 信号 | 触发条件 | 处置 |
| --- | --- | --- |
| 模型失败 | 模型调用或工具校验失败 | `model_error` 状态，不静默重试 |
| 缺证据 | 修订文案引用了未检索到的 fact_id | `insufficient_evidence` 状态 |
| 引用位置不对 | 引文子串未出现在修订文案 | 结构化错误，归并到 `original_checks` |
| 数字未验证 | 修订文案出现证据卡里没有的数字 | 结构化 issue，归并到问题清单 |
| 并发满载 | 服务层信号量达到上限 | 同步接口返回 429 + `concurrency_limit_reached` |

哨兵的每一条都对应一个测试用例；同时缺包时 OTEL 与 Prometheus 全部降级 no-op，不会让缺依赖崩溃核心路径。

## 部署边界

- 单租户、单机的本地单用户审校工作台；
- FastAPI 服务层提供 `POST /v1/audits` 同步接口，可挂载到现有 HTTP 业务流量，默认并发上限 8；
- webhook 推送为可选能力（v0.5.0 引入），需用户配置 `GROWTH_WEBHOOK_URL` 与 `GROWTH_WEBHOOK_SECRET`，无显式启用时不发起任何外联请求；
- 默认无任何第三方网络调用；只有当用户把服务部署到公网或打开 webhook 时才会向外部传 `run_id` 与 verdict 摘要。

## 不在范围内

- 法律合规、保险、监管认证；
- 任何形式的认证或第三方审计结论；
- 商业保密资料、加密、密钥管理。

如需在任何对外材料中使用"已审计""已合规"措辞，先回到本页核对是否超出本说明覆盖范围。
